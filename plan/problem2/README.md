# 第二问：异构无人机多点多架次运输调度

## 1. 题目要求

第二问在**不考虑通信保障**的条件下，研究异构运输无人机多点、多架次运输。每个架次可访问一个或多个服务区，完成投送后返回 `O01`。需联合确定货箱组批、服务区访问顺序、机型、具体执行无人机、共享电池及架次开始时刻。

必须满足货箱不可拆分、载质量与装载体积、返航安全余量、实体无人机和共享电池数量、充电周转及物资时限约束。医疗物资须满足附件的期望送达时间；首批保障货箱须满足首批截止时间；其他物资的期望送达时间用于衡量配送及时性。全部货箱均须完成交付。

需综合优化：配送及时性、全部任务完成时间、运输能耗和架次数，并说明指标权衡。全部任务完成时间定义为所有运输无人机完成最后一个架次并返回 `O01` 的最晚时刻。题目没有规定指标优先级，结果应说明所用优先级/权重，并提供权衡对照，不宜只报告未经解释的单一加权解。

## 2. 输入数据及来源

- `data/无人机应急物资运输基础数据/调度中心与服务区.xlsx`：`O01`、`S001`–`S015` 坐标、地面海拔。
- `data/镇龙乡地理空间数据/镇龙乡及周边地理数据/数字高程模型数据（DEM）/镇龙乡及周边30米DEM.tif`：航段地形剖面；可用同目录 `.mat` 交叉校核。
- 题目规定相邻任务节点采用水平直线航段，巡航海拔为航段 DEM 最高地面高程以上 50 m；`O01` 作业高度为地面海拔，服务区作业高度为地面海拔以上 30 m。多点访问时，每次投送后从 30 m 作业高度重新爬升至下一段巡航高度。
- 为保证可复现，节点间水平距离统一使用第一问采用的大圆测地距离算法；DEM 沿经纬度坐标线性插值路径采样，采样间距不超过 30 m。读取栅格 CRS、分辨率、NoData 和覆盖范围；本项目 GeoTIFF 为 EPSG:4326、约 1/3600 度像元。航段采样遇到范围外或 NoData 时，不得静默填值，应报告并按明确规则处理。航段地面高程取有效路径样本最大值；端点作业海拔仍使用节点表海拔。

### 2.3 货箱与时限

来源：`data/无人机应急物资运输基础数据/物资需求与配送时限.xlsx`。

- `逐箱货箱清单` 当前包含 80 个唯一货箱，字段包括箱号、服务区、物资类型、质量、体积、首批标记、首批截止时间、期望送达时间及应急优先系数。
- 汇总需求表用于对逐箱数据进行箱数、质量与体积交叉核验。
- 以逐箱清单作为分配的基本对象；箱体不可拆分、每箱恰好交付一次，只能送至所属服务区。
- 医疗箱按期望送达时间作硬约束；首批保障箱按其首批截止时间作硬约束。其余箱的期望送达时间作为及时性评价基准。

### 2.4 时间、能耗与充电规则

题目附录 2 规定：

- 载荷 `q` 下等效航程：`L_g(q)=L_g^0-(L_g^0-L_g^F)(q/Q_g)^(3/2)`。
- 航段时间：`t_gij=h⁺/v↑+d_ij/vᶜ+h⁻/v↓`。
- 航段能耗：`E_gij(q)=E_hor_gij(q)+E_up_gij(q)`；下降效率为 0 时不另计下降附加能耗。
- 架次能耗约束：`Σ E_gij(q_pij) ≤ (1-ρ_g) E_g^use`；多点任务中每到一个服务区投放后，后续航段按更新后的剩余载荷计算。
- 电池需从任务结束 SOC 充回 100% 后才可再次使用；同一电池任务占用与充电时段不得重叠。低于 90% 时快速阶段占等效满充时间 65%，90%–100% 慢速阶段占 35%，各段按 SOC 增量线性折算。

题面给出了水平能耗与爬升附加能耗的分解，但未提供完整的水平能耗显式函数。基准实现沿用第一问记录的假设：基准水平单位距离能耗率为 `E_use/L0`（kWh/m），载荷 `q` 下按 `L0/L_g(q)` 缩放，因此 `E_hor(q,d)=E_use*d/L_g(q)`；爬升附加能耗按 `m*g*h/(3.6×10^6×η)`（kWh）计算，并将工作簿爬升效率视为无量纲推进效率。这些是条件性建模假设，不是题目给出的完整水平能耗公式；须对水平能耗率做倍率敏感性分析，并报告公式、单位和适用限制。

### 2.5 架次时间轴与资源周转口径

模板的“开始时刻”未进一步定义。统一规定其填写**固定准备开始时刻**；补充明细分别记录准备开始/完成、装载开始/完成、起飞、各服务区到达与交付完成、返航 `O01`、电池充电开始/完成及无人机下一次可开始准备时刻。基准按准备后装载串行处理；若附件或后续资料支持并行，应据此调整。起飞时刻为准备、装载完成且无人机和电池均可用后的时刻，不能把起飞时刻误填为模板开始时刻。

无人机机体与共享电池是独立资源：机体从准备开始占用到返回 `O01` 后释放。由于运输机参数未给独立返航周转时间，基准假设机体返航即释放、下一架次可开始准备；电池则从本架次准备/装载阶段开始占用至返回，之后开始充电，充至 100% 才能再次分配。下一架次必须同时满足机体可用和所分配电池已充满。更换为另一组已充满的同型电池时，机体不必等待刚用过的电池充电；不得把电池充电时间并入机体占用时间。

## 3. 决策内容与约束

每个架次需确定：所载货箱、访问服务区及顺序、机型、实体无人机、电池、准备开始时刻。还需确定准备/装载/起飞/返航时间、每箱交付完成时刻及各段载荷、能耗和时间。

硬约束至少包括：

1. 每个货箱恰好安排一次，货箱只能在所属服务区交付；
2. 每架次从 `O01` 出发、访问一个或多个服务区并返回 `O01`；
3. 各段载荷不超过机型载质量，架次货箱总体积不超过可用装载体积；投放后正确更新载荷；
4. 按 DEM 规则确定巡航高度，逐段校验时间、能耗和返航 SOC；
5. 实体机机型匹配且任务时段不重叠；
6. 电池与机型匹配，任务占用/充电不重叠，充满后方可再次投入任务；
7. 医疗物资满足期望送达时间，首批保障箱满足首批截止时间；
8. 所有执行过任务的架次均返回 `O01`；不要求闲置无人机执行任务。总体完成时刻取所有运输架次返回 `O01` 时刻的最大值。

交接时间按每个服务区分别计算：基础交接时间加该点交付箱数乘每箱增加交接时间；装载时间按相应机型的每箱装载时间计入。固定准备、装载、交接、飞行、返航和电池充电时间须拆开记录。附件未给运输机返航后的独立周转时间，按 2.5 节的基准假设处理并说明。

## 4. 优化目标与方案比较

建议将硬时限作为可行性约束。迟到基准为逐箱清单的“期望送达时间” `due_b`；医疗物资仍按期望送达时间作硬约束，首批保障箱按首批截止时间作硬约束。软迟到仅对既非医疗物资也非首批保障的其他货箱计算，避免硬约束箱重复计入软目标。软指标至少报告：

- 总迟到秒数：`Σ_b max(0, delivery_b - due_b)`（仅对上述软时限货箱）；
- 应急优先系数加权迟到量：`Σ_b priority_b · max(0, delivery_b - due_b)`（同一软时限集合）；
- 软时限货箱准时率及分物资类型准时率。可选择总迟到、加权迟到或准时率作为优化目标，其余作为报告指标，不要求三者同时优化；
- makespan：最后一个架次返回 `O01` 的最晚时刻；
- 总运输能耗；
- 总架次数。

题目要求综合考虑各指标并说明权衡，但未指定目标函数形式、算法或必须提供 Pareto 前沿。可采用分层/字典序、归一化加权和或其他多目标方法；建议提供替代优先级或代表性 Pareto 解对照以说明取舍，此为建模展示建议而非题目指定算法。避免将秒、kWh、架次未经归一化直接相加；若用加权和，须披露归一化和权重。

计算上可采用“候选架次生成 + 资源调度”：生成满足载荷、体积、航程和返航能量的多点路线/箱组；再做货箱覆盖、实体机与电池分配及开始时刻排程。可用 MILP/CP-SAT 或启发式求解；启发式需报告可行性复核、停止条件和已知界/差距。所有方案应逐航段重放验证，而不只检查汇总能耗。

### 5.2 必需的审计补充与建议图表

模板的两张 Q2 表不能单独展现全部可行性证据。除模板表外，必须通过附加工作表或独立审计文件交付：

- **时间轴与分段**：准备、装载、起飞、逐段飞行、逐服务区交付、返航和下一次可用时刻；逐段载荷、质量/体积、距离、能耗；架次总能耗、返回 SOC 与返航余量检查。

## 6. 与第一问的关系及待确认事项

第二问继承第一问的节点、DEM 处理、巡航高度、航段时间/能耗函数和返航安全口径；但不能沿用第一问“一架次仅一个服务区”的限制。核心新增的是多点路径、逐点卸货后的载荷变化、有限机体、电池周转和时限排程。

实现前应重点处理以下数据/定义边界：

1. 水平能耗公式未完整显式给出；基准假设和单位已在 2.4 节列明，沿用时须开展倍率敏感性分析。
2. 运输无人机数据未单列返航后的架次周转时间；基准假设为机体返航即释放、下一架次可开始准备，电池则充满后才可复用。论文须明确该假设；如获得额外周转参数则替换并重算。
3. 医疗属性与首批标记是不同字段，必须分别检查，不能硬编码为同一类。
4. 若医疗/首批硬时限整体不可行，应报告不可行原因；若另给最小违约备用解，须与满足硬约束的主解区分。
5. 完成时刻以所有已执行运输架次返回 `O01` 时刻的最大值为准；闲置无人机无需执行任务，且不能以最后一个服务区交付时刻代替 makespan。

## 7. 推荐实施步骤

1. 审计并读取空间节点、货箱、机型/实体机、电池输入，核对箱数与汇总需求。
2. 将第一问航段计算扩展为任意节点对、任意当前载荷的可复用函数。
3. 生成并筛选多点候选架次，记录路线、箱组及逐段载荷。
4. 建立货箱唯一覆盖、硬时限约束和目标指标。
5. 分配实体机与共享电池，安排开始时刻并展开充电周转。
6. 求解多个目标优先级/权重情景，比较指标权衡。
7. 独立重放方案，验证货箱、时限、资源、能量及返回时刻。
8. 输出模板表、审计/汇总表、图形和可复现说明；代码建议放在 `src/problem2/`。
