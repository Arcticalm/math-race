# 第三问：通信约束下的运输与中继联合调度

## 1. 题目要求与问题边界

第三问在第二问运输调度的基础上加入通信保障，仍然不考虑问题四的任务分区。运输无人机在爬升、巡航、下降和物资交接全过程必须保持连续双向通信：

1. 与固定网关 `G01` 的直连可用时，采用直连；
2. 直连不可用时，只有运输机—中继机接入链路和中继机—`G01` 回传链路在同一时刻同时可用，才可采用中继；
3. 其余时刻为通信中断，方案不可行；
4. 不允许中继机之间多跳；一架运输机同一时刻最多由 `G01` 或一架中继机保障。

需要联合决定：

- 货箱组批和服务区访问顺序；
- 运输机型、实体运输无人机、共享运输电池和运输架次开始时刻；
- 中继无人机、共享能源组件、悬停经纬度、悬停绝对海拔、建链时刻和服务时段；
- 运输架次与中继服务的匹配关系。

题目要求综合考虑物资配送及时性、联合任务完成时间、运输与中继总能耗以及两类无人机使用架次，并说明指标权衡。联合任务完成时间（makespan）定义为所有已执行运输或中继架次返航到达 `O01` 时刻的最大值；返航后的设备周转不加进返航时刻或 makespan，只用于计算该实体机下一次可用时刻；不要求闲置设备额外执行任务。

## 3. 通信物理模型

### 3.1 三维端点位置

对同一时刻的任意端点，使用 `(longitude, latitude, altitude_m)`：

- `G01`：`O01` 经纬度，地面海拔 + 20 m；
- 运输机：运输航段的水平位置和附录 2 计算的爬升/巡航/下降海拔；服务区交接阶段为服务区作业高度；
- 中继机：选定悬停经纬度和绝对悬停海拔，要求悬停点位于 DEM 有效范围，且 `0 <= z_hover - z_ground <= 300 m`。

运输机分段轨迹固定为：爬升段在起点经纬度垂直变化；巡航段沿相邻节点经纬度线性插值的水平直线移动；下降段在终点经纬度垂直变化；服务区交接期间停留在服务区作业位置及作业高度。每一时刻的水平距离仍按大圆测地距离计算。爬升、下降阶段的高度按附录 2 的分段飞行模型重放。交接位置取服务区节点位置，海拔取节点表地面海拔以上 30 m。中继机到达悬停点后在该点定点悬停。

附件的地理数据说明明确 `DEM.tif` 来源为 Copernicus DEM GLO-30，实际是 DSM（数字表面模型），不是纯地形 DTM。本计划将 DSM 作为地表障碍和中继点地面的代理：无线视线遮挡、运输航段最高地表和中继悬停点离地高度均以 DSM 栅格高程计算；中继点须满足 `0 <= z_hover - z_DSM <= 300 m`。运输机节点作业高度仍按题目节点表/附录规则计算，DSM 用于沿程障碍判定。节点差值采用坐标落入的 DSM 像元值（不做双线性插值）减节点表地面海拔；当前 `O01` 与 `S001–S015` 的差值范围为 `-10.56 m`（`S009`）至 `+7.39 m`（`S008`），`O01` 为 `+1.03 m`。实现时逐节点输出精确差值，不用一方静默覆盖另一方；该差异作为数据口径审计输出。DEM NoData、边界外采样按保守不可行处理，不插补为可用地面。

经纬度到水平距离继续采用第二问的大圆测地距离。三维传播距离为水平大圆距离与垂直高差的欧氏合成，单位转换为 km 后代入 FSPL。运输机与中继机候选端点三维距离 `D=0` 的组合直接排除，避免 `log10(0)`；不额外规定有安全依据之外的最小间距。若两机位置相同但高度不同，三维距离非零时按公式计算。

### 3.2 地形遮挡

对端点连线沿程采样 30 m DEM，并将每个采样位置的地面高程与端点三维视线线性插值高度比较。若任一中间地面点高于或等于视线高度，则：

`b_ij(t) = 1`，表示存在地形遮挡；否则 `b_ij(t) = 0`。

采样必须使用与第二问相同的 CRS、NoData、边界和路径间距处理。端点地面/设备高度与 DEM 采样值不一致时，节点表用于设备作业高度，DEM 用于沿程地形遮挡；差异应记录在审计信息中，不得静默修正。

### 3.3 双向链路预算与状态

对方向 `a -> b`：

`Pth_b = Psens_b + M_b`

`Lmax^(a->b) = Pt_a + Gt_a + Gr_b - Lsys - Pth_b`

双向门限：

`Lmax^(a<->b) = min(Lmax^(a->b), Lmax^(b->a))`

自由空间损耗：

`LFSPL_ij(t) = 32.45 + 20 log10(f_MHz) + 20 log10(D_ij(t)_km)`

总路径损耗：

`Lpath_ij(t) = LFSPL_ij(t) + Lobs * b_ij(t)`

链路可用当且仅当 `Lpath_ij(t) <= Lmax^(i<->j)`。通信状态按优先级判定：

1. `A_transport,G01(t)=1`：直连；
2. 直连不可用且 `A_transport,relay(t)=1`、`A_relay,G01(t)=1`：中继；
3. 否则：中断。

中继接入和回传必须在完全相同的时间段内可用；不能用“两个链路分别在某个时刻可用”替代同步覆盖。

## 4. 决策变量

### 4.1 运输侧

继承第二问的货箱分配、访问顺序、机型、实体机、电池、准备开始时刻和逐箱交付时刻，并增加：

- `c_p(t)`：运输架次 `p` 的通信状态（直连/中继）；
- `r_p(t)`：为其提供保障的中继架次；
- 必要时调整运输架次开始时刻以满足通信和时限。

### 4.2 中继侧

对中继架次 `r` 决定：

- 实体中继无人机 `R01/R02`；
- 共享能源组件；
- 悬停经度、纬度和绝对海拔；
- 准备开始、起飞、到达、建链完成、服务开始/结束、返航和返回 `O01` 时刻；
- 服务的运输架次集合及其通信保障区间。

中继悬停位置可连续优化，也可先在 DEM 有效域内建立候选网格/候选路径点，再用局部搜索细化。候选点必须经过地面高程和离地高度校验。

## 5. 中继时间与能耗模型

### 5.1 中继飞行时间

中继 `O01 -> H -> O01` 的每段按附录 2 的爬升、巡航和下降模型计算。巡航海拔按该航段 DSM 最高地表高程以上 50 m；悬停点终端高度为选定绝对海拔。中继架次的**返回时刻**计算为：

`准备 + 去程飞行 + 建链 + 服务时长 + 返程飞行`。

中继机下一次可用时刻为 `返回 O01 时刻 + 300 s 架次周转`。该周转不加入返航时刻或 makespan。

本计划采用**建链完成即开始服务，不允许到点后等待**的排程口径。中继必须准时出发，使“到达悬停点 + 30 s 建链完成”恰好等于所选服务区间起点；服务区间结束后立即返航。服务开始不得早于运输通信保障区间开始，服务结束不得早于其保障的最后一个运输通信区间结束。需要不同时间段服务时，作为不同中继架次分别排程，不在悬停点安排隐含空等。这样中继返回时刻不含未定义等待，能源计算也不需要估算等待功率。

### 5.2 中继能耗

中继总能耗按以下公式与组成计算：

`E_relay = Σ_leg(P_cruise * t_cruise_h) + Σ_leg(m_plan * g * h_up / (3.6e6 * η_up)) + (P_hover + P_comm) * (t_link_h + t_service_h)`。

去程和返程每段的水平巡航能耗按附件规定的**巡航功率乘巡航时间**计算，`P_cruise=1.15 kW`；不使用运输无人机基于标准航程标定的水平能耗率。爬升附加能耗使用计划起飞总质量 `m_plan=23.5 kg`、`g=9.80665 m/s²` 和爬升效率 `η_up=0.72`，高度 `h_up` 以米计；下降效率为 0，不单独计下降附加能耗。`t_link=30 s` 为到点后的建链悬停时间，建链和服务期间均计悬停功率 `P_hover=1.05 kW` 及通信附加功率 `P_comm=0.05 kW`；通信模块自建链开始即视为工作。没有建链后的等待，因此不存在等待能耗项。附件没有运输机通信设备功耗参数，运输总能耗沿用第二问能耗模型，不另加通信耗电，避免将通信耗电臆测后与等效能耗重复计入。未给定的其他固定能耗不得自行添加。

能源组件约束为：

`E_relay_r <= (1 - 0.20) * 3.2 kWh`。

中继服务时间越长，悬停通信能耗越大，因此不能只按往返飞行能耗选择悬停点。组件返回后按题目两阶段充电模型充至 100%，且同一组件的任务和充电不得与下一架次重叠。

## 6. 硬约束

### 6.1 运输任务约束

继承第二问全部硬约束：

- 每箱恰好交付一次，路线服务区和箱归属一致；
- 载质量、装载体积、航段载荷、等效航程、返航能量和 SOC 可行；
- 医疗期望时间和首批截止时间分别满足；
- 实体运输机和共享运输电池任务/充电不冲突；
- 所有执行过的运输架次返回 `O01`。

### 6.2 中继资源约束

- 只能使用 `R01/R02` 两架中继无人机；同一中继机任务和 300 s 周转时间不得重叠；
- 共享能源组件最多 6 组，同一组件任务和充电时间不得重叠；
- 中继机型、组件型号、能量和返航余量匹配；
- 中继悬停点位于 DEM 覆盖范围，离地高度不超过 300 m；
- 中继架次从 `O01` 出发并返回 `O01`；
- 中继服务开始前必须完成到达和建链，服务结束后才能返航。
- 附件未规定单架中继的并发链路容量，本计划假设一架已建链中继可在同一服务区间同时保障多架运输机，且不因并发对象数增加通信功率；`0.05 kW` 通信附加功率对每架中继按其整个活动服务区间只计一次，不按运输机数量重复计费。并发服务必须同时满足每架运输机的接入链路和该中继至 `G01` 回传链路可用。此项作为显式建模假设，在结果中报告并建议做容量/功率敏感性分析。

### 6.3 连续通信约束

运输架次通信保障区间从实际起飞时刻开始，到返航到达 `O01` 时刻结束；准备和装载阶段不属于空中通信保障区间，若另行评估基地通信，应单独标注。先按去程爬升、去程巡航、去程下降、服务区交接（多点任务逐点拆分）、返程爬升、返程巡航、返程下降生成运动阶段，再按直连/中继保障方式的实际切换时刻切分阶段。模板每行只允许一种保障方式和一种中继架次编号；同一运动阶段内发生多次切换必须拆成多行。所有半开区间互不重叠、首尾衔接，第一行开始等于起飞时刻，最后一行结束等于返航到达时刻；边界切换点只归属其后的区间，不造成双计或空隙。对整个区间 `I_p` 必须满足：

`c_p(t) ∈ {直连, 中继}`，对整个起飞至返航区间成立。

运输机起飞前不要求中继提前提供服务；中继必须在其被分配的保障区间开始前完成飞抵与建链。交接阶段按服务区作业高度和位置判定。中继状态必须同时满足两条链路可用，并且对应中继架次处于已建链的服务区间内。模板通信阶段必须恰好覆盖空中通信保障区间，不留空档、不重叠。

## 7. 优化目标与建议算法

### 7.1 指标定义

至少报告以下指标：

- 运输物资及时性：硬截止违约数（主方案必须为 0）、非医疗物资总迟到秒数、优先系数加权迟到量、准时率；
- 联合任务完成时间：所有已执行运输/中继架次返回 `O01` 时刻的最大值；
- 运输总能耗；中继总能耗；联合总能耗；
- 运输架次数、中继架次数和两类设备的峰值使用数；
- 直连时间、中继保障时间、通信中断时间（主方案中断时间必须为 0）。

题目没有指定目标优先级或必须使用的算法。建议采用分层多目标：先保证货箱全部交付、硬时限和全程通信，再比较及时性、联合完成时间、联合能耗和设备使用架次。每个用于对照的权重/字典序方案或代表性 Pareto 候选，必须在相同输入、物理模型和审计容差下重新通过全部货箱交付、医疗/首批硬时限、连续通信、运输及中继能量、机体与电池/能源组件占用约束；未通过方案只能列为不可行诊断，不得与可行方案目标值并列称为权衡解。报告硬时限合规情况和软期望时间及时性指标。若采用加权和，必须归一化秒、kWh、架次和迟到指标并公开权重。

### 7.2 推荐求解流程

1. **继承第二问候选运输方案**：读取已验证的运输架次、逐段时间和资源占用，保留一个或多个目标权衡方案。
2. **通信可行性预计算**：对每个运输航段/交接阶段采样时间，计算运输机—`G01` 直连可用区间；识别直连缺口。
3. **中继候选点生成**：在 DEM 有效范围建立候选经纬度和离地高度，优先覆盖直连缺口两端，并过滤最大悬停高度、回传链路和接入链路均不可行的点。
4. **候选中继服务区间**：对每个候选悬停点，计算同一时刻接入+回传同时可用的运输覆盖区间；将服务时长、飞行时间和能耗写入候选中继架次。
5. **联合覆盖与资源排程**：用集合覆盖/区间覆盖选择中继架次，使所有运输通信缺口被覆盖，并安排两架中继机、6 组组件和运输资源不冲突。
6. **局部改进**：交换悬停点、服务区间、运输开始时刻和中继机分配，降低中继数量/能耗或改善配送及时性。
7. **独立重放**：按事件断点和自适应细分重新计算地形遮挡、双向链路、通信状态、SOC、资源占用和全部时限；数值采样审计是对连续过程的近似，必须报告误差控制和保守判定规则。

候选搜索可使用固定时间步，但固定步长检查不能单独证明全程连续。最终审计应：

1. 空间上沿视线求交/追踪 DEM 像元边界，在像元穿越点及区间内部检查地面与视线高度；对高程变化或视线余隙接近 0 的区段继续细分。
2. 时间上显式加入飞行阶段端点、交接开始/结束、中继建链/服务开始/结束，以及运输端点移动导致链路门限临界的时刻；对路径损耗接近双向门限的时间区间自适应细分并定位门限交叉。
3. 记录最大空间步长/时间步长、余隙与链路损耗判定容差、细分终止准则和临界区间。候选/输出解若距门限小于误差容差，应按不确定或不可行保守处理，而非直接判可用。
4. 将通信中断时长按细分后验证通过的区间累计；只有全时段均通过保守判定，且累计中断时长为 0（数值容差另行披露）时，才报告“连续通信通过”。此结论仍受 DEM 分辨率和传播模型假设约束，不表述为无误差的连续解析证明。

## 8. 必须输出的结果

### 8.1 模板 Q3 表

`docs/结果提交模板.md` 要求：

**Q3_中继架次**：中继架次编号、中继无人机编号、能源组件编号、开始时刻、悬停经度/纬度/海拔、建链完成时刻、服务结束时刻、返回 `O01` 时刻、架次能耗。模板“开始时刻”统一填固定准备开始时刻；起飞、到达、建链开始/完成、返航后周转完成分别在补充时间轴中记录。“返回 O01 时刻”只记实际返航到达，不含 300 s 返航后周转。

**Q3_通信保障**：运输架次编号、通信阶段、开始时刻、结束时刻、保障方式、对应中继架次编号。

模板中通信阶段至少应能区分爬升、巡航、下降、物资投送/交接和返航；直连阶段的中继架次编号填写空值或 `N/A`，中继阶段填写实际中继架次编号。

### 8.2 必需的补充审计材料

除模板表外，实际交付至少包含：

- **链路明细**：时间、运输机/中继机/G01 三维位置、水平/三维距离、遮挡变量、FSPL、路径损耗、双向门限和链路状态；
- **通信连续性审计**：每个运输架次各阶段的直连/中继区间、覆盖缺口、通信中断秒数和是否通过；
- **中继航段与能耗**：去/返程距离、巡航高度、飞行时间、服务时长、飞行能耗、悬停通信能耗、总能耗、返回 SOC 和能量余量；
- **中继资源审计**：R01/R02 任务、建链/服务/返航区间、返航后 300 s 周转和再次可用时刻；6 组能源组件任务、SOC、充电开始/结束和冲突检查；返航时刻与 makespan 不包含返航后周转；
- **联合运输审计**：继承第二问的箱件覆盖、逐箱交付、运输机/电池、载荷/能量和时限检查；
- **目标摘要**：及时性、联合 makespan、运输能耗、中继能耗、联合能耗、运输/中继架次数、直连/中继占比和代表性权衡方案；
- **空间图和时序图**：运输路线与中继悬停点、通信覆盖区间、运输/中继无人机甘特图、能源组件充电甘特图。

## 9. 数据继承与实现边界

1. 第二问的运输计划不能直接当作第三问最终答案：每个运输架次必须重新经过连续通信审计；通信不可行时，需要插入中继或调整运输时刻/路线。
2. 第二问只验证运输能耗；第三问还必须计算中继巡航、爬升、悬停和通信附加能耗，并把中继组件充电纳入资源排程。
3. 中继悬停位置不能用服务区坐标简单代替；应在 DEM 有效域和最大离地高度约束下搜索，并同时检查运输接入和 `G01` 回传。
4. 链路预算必须读取通信工作簿；传播距离单位必须是 km，频率单位必须是 MHz，功率/增益/损耗必须统一为 dB/dBm/dBi。
5. 连续通信不能只用一个代表点或架次平均值证明；必须对运输机运动路径和中继服务时间进行时序重放。
6. 题面没有规定具体多目标权重、悬停搜索网格或时间步长。程序应把这些作为可配置参数，结果中记录配置，并报告离散化误差/候选点近似。
7. 若在当前设备库存和通信模型下不存在全程通信可行解，应输出不可行诊断，区分原因来自直连缺口、中继覆盖不足、中继机数量、能源组件、能源余量还是运输时限，不能静默放宽通信约束。

## 10. 推荐实施顺序

1. 读取并审计中继机型、实体中继机、能源组件和通信链路参数；
2. 复用第二问运输结果和 DEM 路径采样，建立运输端点的连续时间轨迹；
3. 实现双向链路预算、三维 FSPL、DEM 视线遮挡和通信状态判定单元测试；
4. 预计算直连可用区间和中继候选点的双链路可用区间；
5. 实现中继架次飞行/悬停/能耗/返航/充电模型；
6. 进行运输—中继服务区间匹配、联合资源排程和多目标方案比较；
7. 独立重放所有运输与中继任务，验证连续通信、箱件时限、能量、机体和能源组件资源；
8. 输出模板 Q3 表、问题二继承表、链路/资源审计文件、图形和可复现假设说明；代码建议放在 `src/problem3/`。
