# 第二至第四问统一模式求解

从仓库根目录运行（Python 3.10 或更新版本）：

```bash
.venv/bin/python -m pip install -r final_code/requirements.txt
.venv/bin/python -m final_code.run_all \
  --output outputs/unified/example --rounds 2 --time-limit 120 --max-relays 10
```

输出目录必须为空；程序不覆盖已有结果，也不读取旧 Q2/Q3 方案作为固定输入。
`--time-limit` 是每轮每问四阶段求解的近似总秒数，另有最少单阶段 1 秒和
Q4 反馈偏好阶段；不包含物理评估、通信认证和分区枚举时间。

## 模型与继承关系

1. `patterns.py` 从原始货箱生成共同模式库。初始列来自三种逐区精确集合划分、
   构造式组批、其两区合并方案及所有单箱模式，保留每种物理可行机型。
   模式固定箱号集合、访问顺序、机型、精确交付偏移、返航时间、能耗及充电时间。
   只删除完全重复或物理/最早硬时限不可行的模式，不用运输能耗作跨问题支配剪枝。
2. `master.py` 的第二问用可选区间和逐箱恰好覆盖一次约束，同时选择模式与开始时刻。
   CP-SAT 可以自由混合不同来源的模式；预先生成的完整方案仅作热启动。
   同型无人机、电池分别用累计容量约束，之后按区间图着色分配具体编号。
   同型电池充电曲线必须相同，否则明确拒绝这种等价建模。
3. `communication.py` 为几何相同的模式缓存通信需求。轨迹包含爬升、巡航、下降、
   交接及返程；不能证明全区间直连的时间单元均要求中继。候选悬停点来自服务区坐标
   和现有 P1/P2/P3 地理点，初始高度为附件上限，均检查 DEM 边界、地面高度、回传和能量。
   接入链路用保守移动区间证书及递归细分证明，不能证明的候选不纳入当前库。
4. 第三问在同一模式库上重新选择运输模式和时间，不锁定第二问的组批、机型、
   实体编号或起飞时刻。CP-SAT 同时决定中继任务是否使用、位置、高度、服务窗和
   需求归属。一个中继任务可服务多架运输机，接入容量未给定，沿用无限并发假设。
   中继准备、往返飞行、建链、能量、机体周转、两阶段充电及实体库存都进入主模型。
   联合完成时间包括最后一架中继机返回 O01。
5. 连续时间回代保留整数开始时刻和离散选择，以原始浮点时间、SOC、能耗重算。
   运输、电池、硬时限、巡航净空、中继物理/资源和连续通信均须通过独立审计。
   回代不另行声称连续时间最优，也不擅自提前起飞破坏通信窗口。
6. 第四问读取通过认证的第三问方案。沿用现有程序的严格归属口径：同一运输架次涉及
   的服务区同组，同一中继任务保障的运输架次也同组，不复制或拆分中继任务。
   第三问额外设置三个非空标签保证这种口径下 K=3 可分，合并标签即可得到 K=2。
   标签不禁止第三问使用全局共享资源；各组专属资源仅在冻结后独立核算。
7. 第四问分别枚举 K=2、K=3 的闭包分区，依次最小化总库存缺口、总资源数、最大工作量 CV。
   每个 K 沿用 200,000 候选上限；超过上限明确失败，不把部分枚举称为最优。
   时间轴、路线和保障关系的 CSV 在运行第四问前后核对 SHA-256。
8. 反馈轮从通过审计的 Q3 方案中生成拆分和单箱转移模式，加入共同库，再分别重解 Q2/Q3。
   第四问三组划分作为下一轮末级“减少跨旧组模式”的搜索偏好；不放松前面目标阶段的上界。
   无联合解时扩展模式邻域及候选悬停点/高度，不因限时无解而删除原路线。
   每轮候选用真实回代指标评价，最终保留最好方案，因此后续搜索变差不会覆盖已有结果。

## 目标及最优性边界

第二问依次优化完成时间、加权迟到、运输能耗、架次数；第三问使用联合完成时间、
加权迟到、运输与中继总能耗、总架次数。医疗期望时间和首批截止时间为硬约束。
外层候选先比较上述第三问指标，再比较两种分区的缺口之和、资源量之和及最坏 CV。
此优先级是公开建模选择，没有允许隐含的性能牺牲。

每个目标阶段记录 `OPTIMAL/FEASIBLE/UNKNOWN`、目标值和下界。若某阶段限时只找到
可行解，后续阶段冻结的是该阶段的当前上界；整条字典序链不能据此称为精确最优。
`restricted_lexicographic_optimal` 只有每一阶段都证明最优才成立。

搜索仍然是**有限模式库、有限选址集和保守整数模型中的联合优化**：

- 初始模式库不覆盖所有箱集合/访问排列；每轮默认最多接纳 80 个物理可行邻域提案（每个可有多机型，拒绝项不消耗名额）。
- 运输和中继时间按整秒向安全方向取整，默认时间域 36,000 秒，最多 10 个中继任务槽位。
- 能耗用微 kWh 整数；悬停能耗每秒系数向上取整，充电由保守能耗按两阶段曲线计算。
- Q3 增加了同时支持第四问两种分区的限制；它不等同于无分区要求的原 Q3 全可行域。
- 通信认证相对于附件 DEM/LOS 模型成立；预处理最小细分 1 秒，最终审计最小细分 0.25 秒。
  时间分辨率仅限制证明搜索，任何未得到区间证书的单元都不能判为连续可行。
- 候选模型的最优值或下界不能直接当作原始连续问题的全局下界；回代不能消除遗漏模式。

所以程序始终输出 `global_optimal=false`。路线扩展是启发式邻域搜索，不是带完备定价证明的列生成。

## 输出与复现

- `patterns.json`：最终共用模式库，保留具体箱号、访问序、机型和物理量。
- `q2/`：独立第二问提交表、逐箱/逐段/资源审计、图和验证信息。
- `q3/`：最终联合方案、逐箱交付、运输与中继资源、连续通信审计、模板工作簿及图。
- `q4/`：K=2/K=3 资源配置、库存缺口、工作量和冻结输入哈希。
- `iteration_*/`：各轮求解界、通信需求、通过或未通过审计的候选及分区评价。
- `summary.json`、`feedback_history.json`：最终方案来源及每轮反馈。
- `manifest.json`：Python/依赖版本、原始 Excel/DEM 和算法文件哈希、运行参数。

公共口径沿用原模型：EPSG:4326 经纬度、高度 m、时间 s、能耗 kWh，储备比例 0.2。
运输巡航地形最大值取经过的全部 DEM 像元并加 50 m；中继飞行和 LOS 沿用
`final_code/problem3/physics.py` 的采样物理模型。原始数据不修改。

可复用一次运行保存的通信缓存：

```bash
.venv/bin/python -m final_code.run_all --output outputs/unified/next \
  --profile-cache outputs/unified/example/communication_cache.json
```

缓存必须匹配全部源工作簿、DEM 和几何算法哈希，否则拒绝复用。
最终联合方案仍重新执行独立通信及资源审计。多线程 CP-SAT 的限时结果可能不同，
实际版本与各阶段求解界均保留在输出中。

多个独立运行可按相同指标选择已认证的最好结果（先核对原始数据哈希）：

```bash
.venv/bin/python -m final_code.compare_runs outputs/unified/example outputs/unified/next \
  --output outputs/unified/final
```

第二问和第三问允许来自不同运行；第三问和第四问始终成套继承，不改动任何排程。
各运行的模式编号有独立命名空间，原模式库和来源信息保存在 `sources/`。

## 发布题目要求的结果和图表

统一求解与多次运行筛选完成后，将已选结果发布到 `outputs/unified/` 根目录：

```bash
.venv/bin/python -m final_code.publish \
  --source outputs/unified/final --output outputs/unified
```

根目录包含第二、三、四问各自的提交模板工作簿、程序与结果压缩包，
以及与 `outputs/problem23` 对应的路线、甘特、逐箱送达、时间权衡和巡航净空图。
第三、四问另有中继资源、通信时序、分区地图及库存对照图。
`outputs/unified/README.md` 列出全部图表和提交物。
发布器先核对已选方案的可行性门禁，再复制正式表并从审计数据绘图；
输入方案的排程和冻结分区不会被改动。
